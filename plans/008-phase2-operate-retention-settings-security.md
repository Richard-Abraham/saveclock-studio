## Why this matters

Until now the pipeline can create files but never clean them up, the Settings screen has no disk
numbers, a deleted project leaves its files behind, and the Phase 1 stub is still in the code. This
plan closes those loops so the owner's disk cannot fill silently: intermediates vanish 7 days after
last use, "delete now" removes everything within minutes, an evicted project still renders (its
clips are fetched again), the worker's thread count comes from the one tuning module instead of a
constant written twice (compose default and `detect()`), and a dedicated security pass proves hostile
media, foreign hosts and a second user cannot do harm. It also removes the fake processing, which the
roadmap says Phase 2 must delete.

## Rollback

`git revert` the branch commits (no migration). The stub returns with the revert, so Phase 1's G1 evidence commands work again. Sweeper effects are not reversible (deleted intermediates): the first real run on the owner's volume is a dry run from the worker container, `python -m saveclock.housekeeping_cli --dry-run` (a thin `__main__` that builds a context and calls `services/housekeeping.py` with `dry_run=True`; the API has no `dry_run`), followed by the owner's go and a manual `POST /housekeeping/run`; a project's songs, plans and renders are never swept, so the worst case is a re-fetch at the next render (rehydration), and a clip that vanished at the provider blocks that render until the owner replans.
