## Findings considered and rejected

- Docker-only validation of every script: not worth doing now; the scripts use the shared compose subset and are verified on Podman, the machine in use (note in 003).
- testcontainers for integration tests: rejected for Phase 1 in favour of a loopback-only test compose (001 conflict C17), because rootless Podman has no Docker-API socket by default.
- Torch CPU in the Phase 1 worker image: rejected (no model runs until T-2.2).
- A pre-commit framework and git hooks: deferred; `make check` is the gate and the guard runs in it (001 maintenance notes).
- Librosa for the energy features: rejected (numba needs a writable JIT cache and the containers are read-only); numpy and scipy are enough (plan 004 P4-9).
- A fitted confidence model: deferred, there is no golden set (plan 004 P4-10).
- Dramatiq group fan-out for the fetch stages: rejected for now, one `build_draft` job with an in-process thread pool keeps `uq_jobs_active` simple (plan 005 P5-1).
- Splitting Phase 2 into four plans: rejected, six keeps each plan verifiable in one executor run.
