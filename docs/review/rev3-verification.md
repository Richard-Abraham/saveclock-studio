- Phase P (T-P.0..T-P.11) follows §8b:
  - T-P.0 decides on-device processing, informed by T-0.16.
  - T-P.3: output stays on the device.
  - T-P.1/P.8: minimal data.
  - T-P.2: merchant of record.
  - T-P.4: standard templates.
  - T-P.6: object storage only if server storage remains.
  - Each row states "no counsel step".
- Features that would need legal judgment if Phase P ever happened (flag now):
  1. Selling or distributing videos made from Pexels/Pixabay footage (ADR-0004). See V3-11.
  2. Mode A with a user's commercial song. It is on-device in §8b, but the owner-edition Mode A is a server remux and must not ship to Phase P as-is.
  3. T-P.4 lists NFR-024 ("Legal review of ToS/Privacy/DMCA") as covered. That ID should stay "dropped", not "adapted".
  4. Tailscale Personal is non-commercial (T-0.6 notes this). A public edition can't run on it, but no legal step is needed; it is just a different access path.

## 6. Over-engineering for one user on a private tailnet

Concrete cuts or deferrals (ranked by effort saved):

1. **T-0.16 browser-side feasibility (ONNX Runtime Web, WebCodecs on phone and laptop)** inside Phase 0. It is for Phase P only and delays G0. Move it to the start of Phase P (T-P.0) or Phase 5. Saves roughly a week.
2. **T-2.19 / T-2.21 / T-2.20:** three evaluation-harness modes (`ci-lite`, `nightly`, `release`), paired bootstrap, determinism check, rating app, A/B sign-test protocol (QUALITY §8, §5.4), VMAF in `verify_render`. Keep one local `make eval` command (mean-based gates) and the per-render Block checks (QM-060..064, 068). Defer paired bootstrap, nightly runner and the rating tool (a spreadsheet is enough).
3. **QUALITY catalog (77 metrics)**, mainly Own/Rpt rows with no gate: QM-082, 083, 084, 100-106 and the QM-090..093 split. Keep them as a "report" appendix, not ROADMAP-owned IDs; this also shrinks Appendix A (about 500 lines of generated mapping).
4. **SECURITY 75 controls:** several are CI ceremony for a private tool: SEC-092/093 (image scanning plus hadolint), SEC-094/095/098/099 (2FA and disk-encryption evidence in T-1.17), CSP report-only soak plus HSTS and nosniff header tests (T-1.15), T-1.16 container sandbox verification matrix. Keep secret scan, config-malware guard, non-root, no published ports, backups. Fold the rest into a one-page checklist (CHECKLIST.md already exists).
5. **Chunked resumable upload (endpoints #6-10, 8 MiB parts, per-part sha256, resume info, abort)** for a 100 MB file over a private tunnel. One streamed `POST /projects/{id}/song` with a size limit would do, unless T-0.15 shows a proxy limit. Saves 4 endpoints and the `_incoming/` assembler. (The docs already allow this: T-0.15 tests the 100 MB path.)
6. **Signed file tokens (`GET /files/{token}`, HMAC, TTL, `FILES_SIGNING_KEY`, #19 expiry, #25)** on a tailnet with the owner as the only reader. Serve renders from authenticated routes (`GET /renders/{id}/file?kind=`). Removes a key, an env var and a token test suite. Keep it only if T-0.15 shows the browser can't send the identity header on media requests.
7. **Edit-plan machinery:** versioned immutable plans with `base_version`, `op_id` idempotency, frozen versions, `plans/{version}` endpoint, `content_hash`, `job_hash`, `idempotency_key` columns on renders and exports (ARCH §5, §6, §7 #16-17, #21, #24). For one editor tab, keep a working plan, a "frozen at render" copy, and last-write-wins.
8. **Tables and endpoints:** `exports` table (Mode A only; fold into `renders`), `GET /housekeeping/disk-usage` and `POST /housekeeping/run` (fold into `GET /settings/storage`/a button), #32/#33 settings endpoints (an env flag for Pixabay is enough, which also removes `users.settings` and the DB CHANGE it forces; the fixes log already offers this), #12 cancel plus #23 cancel render (one `POST /jobs/{id}/cancel`), #16, #26. This is 33 down to about 24 endpoints.
9. **Phase 0 scope creep:** FFmpeg 8.1 vs 9.0 six-row comparison with mean-VMAF parity (G0-20..25) and building both from source; a 50-track golden set with self re-annotation and a week-later blind re-label; 5 raters; contended-load p95 under three profiles. A 30-track core set, FFmpeg 8.1.x only (9.0.x only if the frame test fails), and one contended run suffice for a go/no-go.
10. **Process ceremony per task:** every phase has a `T-n.0` plan, a `ponytail-review` task, a change summary task and an owner confirmation (about 25 rows of pure process). Keep the rule in the header table and drop the per-phase rows, or keep only the plan row.
11. **Services and infra:** separate `worker-maint` container (the queue can run in the same worker process), app_rw/migrator DB role split, Sentry, ntfy alerts, Trivy, quarterly restore drills, 14-day dogfood. Keep nightly encrypted backup plus one tested restore.
12. **Docs volume:** ARCHITECTURE is 1033 lines with 25 sections (capacity model, cost model, Phase P seams, open-question lists) and QUALITY is 726 lines with sections that restate Rev 2 history. Archive the history blocks and keep the current spec.
